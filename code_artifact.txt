一、 重构目标与核心业务边界
================================================================================

1.1 现状核心问题（重构必须消除的病灶）
- 双轨并存：旧版异步任务轨（`DisasterSurveyTaskManagerController`、`EvaluateTaskManagerController`、`ExecuteEvaluateScheduleTask`）与新版前端驱动补丁轨（`StepComputeController`、`BizFrontendDataController`）混杂；定时器注解已被注释停用且残留其他项目注释（如“水质插值评价任务”）。
- 万能表滥用：`T_BIZ_FRONTEND_DATA`（`BizFrontendDataModel`）把各类业务结果直接存成无结构 JSON，导致业务不可追溯。
- 命名分裂：同一承灾体存在三套命名（后端 Entity：`Dike/Fishery/CultureArea/TouristArea`；前端：`seawall/fishing/mariculture/tourist`；业务配置：中文名称）；灾害类型存在冗余映射（如 `storm/economic`、`wind/seabreeze`、`wave/seawave`）。
- 上下游断层：灾情调查产出未通过统一主线（事件ID + 基线版本）严谨传递给灾害评估。
- Mock 污染：前端在接口失败或无数据时静默回落到本地 Mock 数据，掩盖真实接口问题。

1.2 重构后的业务定位与主线
- 顶层主线：引入【灾害事件 (`DisasterEvent`, `event_id`)】贯穿全链路：
  `灾害事件 (Event)` -> `灾情调查 (产出已确认的调查基线 Baseline)` -> `灾害评估 (风暴潮/海风/海浪)` -> `综合评估报告归档 (Report)`
- 灾情调查模块（客观事实层：摸底数、核真伪）：
  1) 基础底数查询（行政区划、人口密度、4类承灾体）
  2) 遥感影像受灾范围识别（提取受灾面 Polygon）
  3) 多维空间叠置分析与影像导出（受灾人口、乡镇受灾面积、4类受灾承灾体清单及影像导出）
  4) 遥感分析结果与灾情速报上报数据对比核查 -> 固化为《调查基线》
- 灾害评估模块（研判决策层：析机理、算损失、出报告）：
  1) 风暴潮评估：受灾信息标准化整合 -> 灾后经济损失评估 -> 风暴潮灾后综合评估
  2) 海风评估：SAR海风破坏性分析 -> 卫星海风行为分析 -> 海风综合评估
  3) 海浪评估：SAR海浪破坏性分析 -> 卫星海浪行为分析 -> 海浪灾后综合评估
  4) 统一评估报告生成与归档管理

二、 全局统一领域字典与枚举规范（前后端强一致）
================================================================================

请在后端 `disaster-survey-core` 中新建枚举包 `com.santech.core.framework.entity.enums.biz`，并在前端新建统一常量文件（如 `src/constants/disasterEnums.js` 或 `.ts`），前后端严格使用以下编码：

2.1 灾害类型枚举 (`DisasterTypeEnum`)
- `STORM_SURGE` : 风暴潮（替代旧的 storm / economic 等混用）
- `SEA_WIND`    : 海风（替代旧的 wind / seabreeze 等混用）
- `SEA_WAVE`    : 海浪（替代旧的 wave / seawave 等混用）

2.2 承灾体类型枚举 (`ExposureTypeEnum`)
- `SEAWALL`      : 海堤 / 海岸防护工程（对应实体 `BaseDikeModel`）
- `FISHING_PORT` : 渔港（对应实体 `BaseFisheryModel`）
- `MARICULTURE`  : 海水养殖区（对应实体 `BaseCultureAreaModel`）
- `TOURIST_AREA` : 滨海旅游区（对应实体 `BaseTouristAreaModel`）

2.3 评估子项枚举 (`AssessmentSubTypeEnum`)
- 风暴潮：`STORM_INFO_INTEGRATION`（信息整合）、`STORM_ECONOMIC_LOSS`（经济损失）、`STORM_COMPREHENSIVE`（综合评估）
- 海风：`WIND_DAMAGE_ANALYSIS`（破坏性分析）、`WIND_BEHAVIOR_ANALYSIS`（行为分析）、`WIND_COMPREHENSIVE`（综合评估）
- 海浪：`WAVE_DAMAGE_ANALYSIS`（破坏性分析）、`WAVE_BEHAVIOR_ANALYSIS`（行为分析）、`WAVE_COMPREHENSIVE`（综合评估）

2.4 调查基线状态枚举 (`BaselineStatusEnum`)
- `DRAFT`     : 草稿/调查中（可修改、重算）
- `CONFIRMED` : 已核查确认（只读锁定，可作为下游灾害评估的正式输入）
- `ARCHIVED`  : 已归档

2.5 异步计算任务状态枚举 (`ComputeTaskStatusEnum`)
- `CREATED`   : 已创建
- `RUNNING`   : 计算中
- `SUCCEEDED` : 已完成
- `FAILED`    : 失败

三、 数据模型与数据库表重构设计

涉及文件：

需要建立/升级以下 5 张核心结构化业务表（全部通过 `event_id` 关联）：

3.1 灾害事件主表：`T_BIZ_DISASTER_EVENT`（新增）
- `id` (PK, VARCHAR) : 事件唯一ID (`event_id`)
- `event_code` (VARCHAR) : 事件编号
- `event_name` (VARCHAR) : 灾害事件名称（如“2026年第X号台风风暴潮灾后调查”）
- `disaster_types` (VARCHAR) : 涉及灾种（逗号分隔，取自 `DisasterTypeEnum`）
- `region_code` (VARCHAR) : 沿海区县行政区划编码
- `region_name` (VARCHAR) : 行政区划名称
- `occur_time` (TIMESTAMP) : 灾害发生时间
- `status` (VARCHAR) : 事件状态 (`ACTIVE` / `CLOSED`)
- `create_time`, `update_time`, `create_by`

3.2 灾情调查基线表：`T_BIZ_SURVEY_BASELINE`（重构升级现有 `BizSurveyBaselineModel`）
- `id` (PK, VARCHAR) : 基线ID (`baseline_id`)
- `event_id` (VARCHAR, NOT NULL) : 关联 `T_BIZ_DISASTER_EVENT.id`
- `version_no` (INT) : 基线版本号
- `status` (VARCHAR) : `DRAFT` / `CONFIRMED` / `ARCHIVED`
- `rs_image_id` (VARCHAR) : 使用的灾后遥感影像资源ID
- `affected_area_geojson` (TEXT/CLOB) : Step2 识别出的受灾范围矢量面
- `affected_population` (DECIMAL/INT) : Step3 受灾人口预估
- `town_area_stats_json` (TEXT/CLOB) : Step3 乡镇受灾面积预估列表
- `exposure_overlay_json` (TEXT/CLOB) : Step3 4类受灾承灾体叠置清单（按 `ExposureTypeEnum` 分组）
- `compare_check_json` (TEXT/CLOB) : Step4 遥感解译 vs 速报上报对比核查结果（差异项与核定值）
- `confirmed_time`, `confirmed_by`, `create_time`, `update_time`

3.3 承灾体现场核查档案表：`T_BIZ_HAZARD_DOSSIER`（规范现有 `BizHazardDossierModel`）
- 补充/规范字段：`event_id`、`baseline_id`、`exposure_type`（严格使用 `ExposureTypeEnum`）、`exposure_id`、`rs_clip_image_url`（导出的承灾体遥感影像路径）、`field_attachments_json`（现场核查照片/附件）。

3.4 灾害评估记录表：`T_BIZ_ASSESSMENT_RECORD`（新增，取代 `T_BIZ_FRONTEND_DATA` 的评估数据存储）
- `id` (PK, VARCHAR) : 评估记录ID (`assessment_id`)
- `event_id` (VARCHAR, NOT NULL) : 关联灾害事件
- `baseline_id` (VARCHAR) : 关联已确认的调查基线（风暴潮评估强关联，风/浪评估可选关联）
- `disaster_type` (VARCHAR, NOT NULL) : `STORM_SURGE` / `SEA_WIND` / `SEA_WAVE`
- `sub_type` (VARCHAR, NOT NULL) : 取自 `AssessmentSubTypeEnum`
- `region_code` (VARCHAR) : 评估区县编码
- `input_params_json` (TEXT/CLOB) : 评估输入参数（如坐标、SAR影像ID、经济/土地底数快照、标准化速报数据）
- `result_data_json` (TEXT/CLOB) : 结构化计算结果（经济损失明细、风/浪破坏等级、淹没/侵蚀估测、综合评分因子）
- `compute_mode` (VARCHAR) : `SYNC`（同步推算） / `ASYNC`（外部模型异步计算）
- `status` (VARCHAR) : 取自 `ComputeTaskStatusEnum`
- `create_time`, `update_time`, `create_by`

3.5 评估报告归档表：`T_BIZ_REPORT_ARCHIVE`（规范现有 `BizReportArchiveModel`）
- 补充/规范字段：`event_id`、`assessment_id`、`disaster_type`、`report_title`、`report_file_path`、`report_format`（DOCX/PDF）、`summary_json`（报告核心结论摘要）、`create_time`。

3.6 废弃表处理
- `T_BIZ_FRONTEND_DATA`（`BizFrontendDataModel`）：停止向其写入任何新的调查/评估业务数据；待现有前端页面全部切换到新接口后，将其标记 `@Deprecated` 并清理。

4.3 规范后的 REST API 契约（统一前缀与语义）
【灾害事件】
- `POST /api/v1/disaster-events`                     : 创建灾害事件
- `GET  /api/v1/disaster-events`                     : 分页查询事件列表
- `GET  /api/v1/disaster-events/{eventId}`           : 查询事件详情（含关联的基线与评估进度概览）

【灾情调查模块 - 4步闭环】
- Step1 基础底数：
  - `GET  /api/v1/survey/base/region-population`     : 按区县/坐标查询行政区划与人口密度
  - `GET  /api/v1/survey/base/exposures`             : 按区县/类型查询4类承灾体基础台账与空间位置
- Step2 遥感范围识别：
  - `POST /api/v1/survey/events/{eventId}/affected-area` : 加载/解译灾后遥感影像，保存受灾范围 GeoJSON
- Step3 叠置分析与影像导出：
  - `POST /api/v1/survey/events/{eventId}/overlay-analysis` : 执行受灾范围与人口/乡镇/4类承灾体空间叠置分析
  - `POST /api/v1/survey/events/{eventId}/exposure-images/export` : 按4类承灾体导出对应区域灾后遥感影像
- Step4 对比核查与基线固化：
  - `POST /api/v1/survey/events/{eventId}/compare-quick-report` : 接入灾情速报数据，与遥感结果对比生成柱状图/表格数据
  - `POST /api/v1/survey/events/{eventId}/baseline/confirm` : 确认核查结果并锁定《调查基线》
  - `GET  /api/v1/survey/events/{eventId}/baseline`  : 获取最新调查基线详情
  - `GET/POST /api/v1/survey/events/{eventId}/dossiers` : 承灾体现场核查档案管理

【灾害评估模块 - 三灾种分轨 + 报告】
- 风暴潮：
  - `POST /api/v1/assessment/events/{eventId}/storm-surge/integrate`     : 速报受灾信息标准化整合
  - `POST /api/v1/assessment/events/{eventId}/storm-surge/economic-loss` : 经济损失评估测算
  - `POST /api/v1/assessment/events/{eventId}/storm-surge/comprehensive` : 风暴潮综合评估
- 海风：
  - `POST /api/v1/assessment/events/{eventId}/sea-wind/damage`           : SAR海风破坏性分析
  - `POST /api/v1/assessment/events/{eventId}/sea-wind/behavior`         : 海风行为分析
  - `POST /api/v1/assessment/events/{eventId}/sea-wind/comprehensive`    : 海风综合评估
- 海浪：
  - `POST /api/v1/assessment/events/{eventId}/sea-wave/damage`           : SAR海浪破坏性分析
  - `POST /api/v1/assessment/events/{eventId}/sea-wave/behavior`         : 海浪行为分析
  - `POST /api/v1/assessment/events/{eventId}/sea-wave/comprehensive`    : 海浪综合评估
- 评估记录与报告归档：
  - `GET  /api/v1/assessment/events/{eventId}/records`                   : 查询事件下所有评估子项记录
  - `POST /api/v1/assessment/events/{eventId}/reports/generate`          : 生成风暴潮/海风/海浪综合评估报告
  - `GET  /api/v1/assessment/reports`                                    : 报告归档列表与下载
